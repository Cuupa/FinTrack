### DONE — Bugfix: /analysis risk KPIs collapse on a stub holding (2026-08-21)
Reported "risiken ist kaputt": the portfolio-level tiles (Sharpe, Sortino, Beta, Alpha = "—"; Volatilität + VaR = "0,0 %") were dead while the per-position table computed fine. Root cause (pre-existing, the stabilization pass never touched this code — verified via git log): one freshly listed holding with a 1-2 point in-window history poisoned BOTH aggregate paths.
- `portfolioRiskStats` (`lib/finance/stats.ts`) truncated EVERY return series to `L = min(lengths)`. One holding with a single in-window monthly return made `L=1`; `corrcoef` returns 0 for `n<2` **including the diagonal**, so `variance→0`, `volatility→0`, and `sharpeRatio`/sortino returned null (div-by-zero guards), VaR 0. Fixed: covariance is now computed **per pair on the tail each pair shares**, self-pair = 1 (`tailCorr` helper). Each asset keeps its own measured vol; a pair with too little overlap adds no covariance. For equal-length series this is **bit-identical** to the old alignment (the old diagonal was already 1). Downside/Sortino path now built only from holdings with >=2 returns, weights renormalised.
- `compositeLevelSeries` (`lib/finance/returns.ts`, drives portfolio Beta/Alpha, also used by the LLM context) intersected ALL holdings' dates; the same stub shrank the shared window below 3 -> `[]` -> Beta/Alpha "—". Fixed: when the full intersection is <3 it drops the shortest-history holdings one at a time (weights renormalise over the survivors) until they share a usable window. Single-holding bit-identical guarantee preserved.
- Tests: `tests/portfolio-risk.test.ts` (4) — reproduces the stub-collapse for both functions; VERIFIED they fail on the pre-fix code (2 core assertions red) and pass after. Full unit **1324/0**, e2e **77/0**, tsc + eslint clean. No other finance calc touched; healthy portfolios unchanged.
